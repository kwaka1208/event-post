# Fireside 再設計

クローズドなグループのためのイベント管理システムとして作り直す。トップページ以外は、承認された Google アカウントだけが見られる。

## 決めたこと

| 項目 | 方針 |
|---|---|
| グループの数 | 1 サイト 1 グループ。グループごとに Firebase のプロジェクトを用意してデプロイする |
| グループの作成 | デプロイ後、最初にログインした人が `/setup` で作る。作った人が特権管理者になる。2 つ目は作れない |
| 画面 | Vite＋React＋React Router＋TanStack Query の SPA（`web/`） |
| ホスティング | GitHub Pages（ほかのサイトと運用を揃える）。Firebase の Web 設定はビルド時に環境変数 `VITE_FIREBASE_*` で埋め込む（Actions ではリポジトリの Variables `FIREBASE_*` から渡す）。どのパスでも画面を出せるよう、`index.html` を `404.html` に複製する。サブパスは環境変数 `BASE_PATH` で渡す |
| データ | Cloud Firestore。アクセス制御はセキュリティルールで行う。無料の Spark プランで動かす（Cloud Functions は使わない） |
| メール | GitHub Actions が毎時 Firestore を見て、Gmail から送る。最大 1 時間ほど遅れて届く |
| 申込データ | 自動では削除しない（マイページで過去の参加を見せるため） |

## 役割と権限

役割は `owner`（特権管理者）、`admin`（管理者）、`member`（参加者）の 3 つ。`owner` はグループを作った 1 人だけ。

| 操作 | 未登録 | 参加者 | 管理者 | 特権管理者 |
|---|:-:|:-:|:-:|:-:|
| トップページを見る | ○ | ○ | ○ | ○ |
| 参加を申し込む | ○ | | | |
| イベントを見て申し込む（これから・過去） | | ○ | ○ | ○ |
| マイページを見る、自分の名前を変える | | ○ | ○ | ○ |
| メンバー一覧を見る、自分の自己紹介・URL・画像を設定する | | ○ | ○ | ○ |
| 退会する（開始前の申込は自動でキャンセル） | | ○ | ○ | |
| 管理者に問い合わせる | | ○ | ○ | ○ |
| 掲示板を読む・書く、自分の書き込みを消す | | ○ | ○ | ○ |
| 掲示板のほかの人の書き込みを消す | | | ○ | ○ |
| 申し込みを参加者として承認する・削除する | | | ○ | ○ |
| 申し込みを管理者として承認する | | | | ○ |
| イベントを作成・編集する | | | ○ | ○ |
| 参加者を削除する・メールを送る | | | ○ | ○ |
| 管理者を削除する・役割を変える | | | | ○ |
| 配色（テーマカラー）を変える | | | ○ | ○ |
| グループ名・説明を変える | | | | ○ |

- 特権管理者は削除できない
- グループから削除された人や退会した人は、もう一度参加を申し込める
- 退会は、開始前のイベントの申込をキャンセルしてから `members` を消す。開始後の申込は記録として残す

## データ（Firestore）

| パス | 中身 | 読める人 |
|---|---|---|
| `group/profile` | グループ名、説明、特権管理者の名前と uid、テーマカラー（`accentColor`。ないこともある） | 誰でも |
| `members/{uid}` | 役割、本名、ニックネーム、メールアドレス、参加日時、タグ（管理者が付ける分類。ないこともある） | 本人と管理者 |
| `directory/{uid}` | メンバー一覧に出す内容（ニックネームの写し、自己紹介 100 文字まで、URL 1 つ、画像。画像はないこともある） | メンバー（書けるのは本人だけ） |
| `applications/{uid}` | 本名、ニックネーム、申し込み理由、メールアドレス、申込日時、通知の送信日時 | 本人と管理者 |
| `events/{id}` | タイトル、本文（Markdown）、日時、会場、住所、定員、締切、公開状態、申込数 | メンバー（下書きは管理者だけ） |
| `events/{id}/registrations/{uid}` | イベントへの申込（名前とメールアドレスの写し、申込日時、受付メールとリマインドの送信日時） | 本人と管理者 |
| `mails/{id}` | 管理者が書いたメール（宛先、件名、本文、送信状況） | 管理者 |
| `topics/{id}` | 掲示板の話題（書いた人の uid とニックネームの写し、タイトル、本文、作成日時、最後の投稿日時、最後の返信の ID） | メンバー |
| `topics/{id}/replies/{id}` | 話題への返信（書いた人の uid とニックネームの写し、本文、作成日時） | メンバー |
| `inquiries/{id}` | メンバーから管理者への問い合わせ（送った人の名前とメールアドレスの写し、件名、本文、通知の送信日時） | 管理者 |

- グループの作成は 1 回の書き込みで行う（`group/profile` と自分の `members`、`directory` を同時に作る）
- 承認も 1 回の書き込みで行う（`members` と空の自己紹介の `directory` を作り、`applications` を消す）
- `directory` は、`members`（本名とメールアドレスがあり、本人と管理者しか読めない）とは別に、メンバー全員に見せるものだけを持つ。ニックネームは書いた後の `members` と同じでなければならず、名前の変更と同じ書き込みでそろえる。退会と削除では `members` と同時に消す。URL は空か、`http://`・`https://` で始まり空白を含まないもの
- この機能より前からいるメンバーの `directory` は、管理者が `/admin/members` を開いたときに、空の自己紹介で足す（もうメンバーでない人の分は消す）。管理者が書けるのは空の自己紹介だけ
- イベントへの申込とキャンセルは、`registrations` の作成・削除と申込数の ±1 を同時に書く（定員をルールで守るため）
- 返信は、`replies` の作成と、話題の `lastPostedAt`・`lastReplyId` の更新を同時に書く（一覧を最後の投稿の新しい順に並べるため。`lastReplyId` で、返信を作らずに話題だけを上げることを防ぐ）
- 話題を消すときは、画面が返信を 1 件ずつ消してから話題を消す（まとめて消すとルールの get の回数の上限を超えるため）。返信を消せるのは、書いた人、管理者、話題を立てた人
- タグは `members` の `tags`（文字列のリスト、1 人 10 個まで）。付け直せるのは管理者だけで、ほかの項目と同時には変えられない。タグの一覧は別に持たず、メンバーに付いているタグから作る。メールの宛先の「タグで選ぶ」は、選んだタグのどれかが付いている人
- 掲示板の書き込みは直せない（消して書き直す）。メールでの通知はしない
- マイページは `registrations` を collectionGroup で検索して、自分の分を取り出す
- プロフィール画像は、Cloud Storage を使わず（Spark プランでは使えないため）、ブラウザで 192px 四方の JPEG にして `directory` の `photo` に data: URL で入れる（1 枚 数 KB〜数十 KB。ルールで JPEG・PNG・WebP の data: URL、10 万字までに限る）。管理者が足す `directory` には画像を付けられない
- テーマカラーは `group/profile` の `accentColor`（`#rrggbb`）。管理者が変えられ、ほかの項目と同時には変えられない。読みやすさ（背景とのコントラスト比 4.5 以上）は画面で確かめ、画面は読み込んだ色を `--accent` に当てる。次に開いたときに標準の色が一瞬見えないよう、ブラウザにも覚えておく
- 名前の変更は、`members` を書いたあと、開始前のイベントの `registrations` の名前の写しを 10 件ずつそろえる（ルールの get の回数の上限に収めるため）。開始後の申込は当時の名前のまま残す

## 画面

| パス | 画面 | 見られる人 |
|---|---|---|
| `/` | トップページ（グループ名、特権管理者の名前、説明、Google でログイン） | 誰でも |
| `/setup` | グループの作成 | グループがまだないときだけ |
| `/join` | 参加申し込み（本名、ニックネーム、理由）。送ったあとは「承認待ち」を表示 | 未登録 |
| `/events`、`/events/:id` | イベントの一覧（これから・過去）、詳細と申込 | メンバー |
| `/board`、`/board/new`、`/board/:id` | 掲示板（話題の一覧、話題を立てる、話題と返信） | メンバー |
| `/members` | メンバー一覧（画像、ニックネーム、自己紹介、URL をひとり一行で） | メンバー |
| `/me` | マイページ（申し込んだイベント、参加したイベント、自分の名前の変更、自己紹介・URL・画像、退会） | メンバー |
| `/contact` | 管理者への問い合わせ | メンバー（メニューに出すのは参加者だけ） |
| `/admin/applications` | 申し込み一覧（役割の選択、承認、削除） | 管理者 |
| `/admin/members` | メンバー管理の一覧（役割ごと・タグごとに、ひとり一行。全員または選んだ人へのメール） | 管理者 |
| `/admin/members/:uid` | メンバーの詳細（メールアドレス、参加日時、役割の変更、タグの付け直し、削除） | 管理者 |
| `/admin/events` | イベントの作成・編集 | 管理者 |
| `/admin/inquiries` | 届いた問い合わせの一覧（返信、削除） | 管理者 |
| `/admin/settings` | 設定（グループの情報は特権管理者だけが変えられる。配色は管理者が変えられる） | 管理者 |

## メール（毎時の Actions）

- 新しい参加申し込み → 管理者全員に通知
- 承認 → 本人に通知
- イベントへの申込 → 受付メール
- 開催前日 → リマインド
- 管理者が画面で書いたメール → 指定した宛先へ
- イベントのお知らせ → メンバー全員へ。イベントを公開して保存するときに選ぶと、画面がお知らせの文面で `mails` を作る（送り方は管理者が書いたメールと同じ）
- メンバーからの問い合わせ → 送った人を除く管理者全員へ（返信先は送った人）
